# RFC process

An RFC is a request for comments on a proposed design. It does not establish that a feature exists or has been accepted.

1. Read the [roadmap](../docs/ROADMAP.md) and check existing [issues](https://github.com/Monotoba/SageIDE/issues) and RFCs for related proposals.
2. Copy [RFC_TEMPLATE.md](RFC_TEMPLATE.md) into a new file in this directory. Use the next available number, following the existing filename pattern, such as `rfc-00002.md`.
3. Explain the problem, proposed behavior, alternatives, risks, and observable acceptance criteria. Mark the proposal as a draft.
4. Commit the file on your branch and open a pull request. Use pull request comments for discussion.
5. Revise the proposal in response to review. Maintainers record whether it is accepted, deferred, or rejected.
6. For an accepted proposal, implement it in focused changes with tests and updated documentation. Acceptance of an RFC is separate from completion of its implementation.

Follow the [Code of Conduct](../CODE_OF_CONDUCT.md) throughout the discussion.
